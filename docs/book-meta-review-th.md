# ขอบเขตที่ต้องตรวจยืนยันก่อนเปิดส่งยอดเข้า Meta

วันที่ 2 ตุลาคม 2569 | สถานะ: ติดตั้งระบบแล้ว ปิดการส่งจริงอยู่

## สิ่งที่จะเปิด

ส่งออเดอร์ใหม่ที่สั่งผ่านหน้าเว็บรุ่นที่แสดงประกาศแล้ว เข้า Pixel เดิม 300488034391029 ของเด็กประกอบการ ผ่าน Conversions API ไม่แก้แอด งบ ลิงก์ หรือกลุ่มเป้าหมาย

- OrderSubmitted = สั่งซื้อสำเร็จ พร้อมยอดสินค้า
- Purchase = ทีมงานยืนยันรับเงินจริงแล้ว พร้อมยอดที่รับ
- ไม่มีป๊อปอัป ไม่มีช่องติ๊กยินยอมบังคับ ไม่มีการส่งข้อมูลคนที่แค่เปิดเว็บ
- มีข้อความแจ้งก่อนปุ่มสั่งซื้อ และปุ่มคัดค้านในรายละเอียดความเป็นส่วนตัว ซื้อได้ตามปกติแม้คัดค้าน
- ไม่ส่งออเดอร์เก่าย้อนหลัง

## ข้อมูลที่จะออกจากระบบ

ส่งไป Meta Platforms, Inc.: เบอร์โทรที่แฮช SHA-256, ชนิดเบราว์เซอร์, รหัสคลิกของ Meta ถ้ามี, ประเภทเหตุการณ์, เวลา, ยอดสินค้าและสกุลเงิน, รหัสเหตุการณ์สุ่มที่ผูกกับออเดอร์ และ URL หน้าขายที่ตัดพารามิเตอร์แล้ว

ไม่ส่งชื่อ ที่อยู่ สลิป หมายเหตุ เลขบัญชี หรือเบอร์โทรแบบอ่านได้ ไม่สร้างคุกกี้โฆษณา และไม่เก็บ IP เพิ่มสำหรับระบบนี้

รหัสแฮชยังเป็นข้อมูลส่วนบุคคล Meta ใช้ข้อมูลเหตุการณ์เพื่อการจับคู่ วัดผล และปรับปรุงโฆษณาตามเงื่อนไขของ Meta รวมถึงการใช้งานที่กว้างกว่ารายงานของบริษัท ข้อมูลอาจประมวลผลในต่างประเทศ เก็บข้อมูลจับคู่ในระบบบริษัทไม่เกิน 90 วัน ส่วน Meta ระบุว่าอาจเก็บข้อมูลเหตุการณ์สูงสุด 2 ปี

## การประเมินที่ยังต้องให้ผู้ควบคุมข้อมูลยืนยัน

ฐานที่เสนอคือประโยชน์โดยชอบด้วยกฎหมายเพื่อวัดผลโฆษณา ไม่ใช่ความจำเป็นในการจัดส่ง และไม่ใช่ความยินยอมที่ถือเอาจากการซื้อสินค้า

ประโยชน์: แยกยอดขายตามแอดเดิมเพื่อจัดงบได้ถูกต้อง รายงานรวมอย่างเดียวตอบไม่ได้

ผลกระทบ: ลูกค้าอาจไม่คาดหวังให้เบอร์โทรที่กรอกเพื่อส่งสินค้าถูกนำไปจับคู่กับบัญชี Meta และข้อมูลอาจถูกใช้เพื่อปรับการแสดงโฆษณา จึงต้องชั่งน้ำหนักความจำเป็น ความคาดหมายของลูกค้า สิทธิคัดค้าน และมาตรการโอนข้อมูลต่างประเทศ

มาตรการลดผลกระทบถูกทำไว้แล้ว แต่การมีประกาศและปุ่มคัดค้านไม่ทำให้ฐานกฎหมายใช้ได้โดยอัตโนมัติ ต้องมีข้อสรุปและหลักฐานการประเมินจากบริษัท/ผู้รับผิดชอบข้อมูลก่อนเปิด หากผลประเมินไม่รองรับ ต้องคงปิดหรือใช้ความยินยอมจริง การอนุมัติสร้างโทเค็นไม่ใช่การยืนยันฐานกฎหมาย

## สิทธิ์เชื่อมต่อที่ต้องอนุญาต

สร้างโทเค็น CAPI สำหรับชุดข้อมูลข้างต้นแบบไม่เพิ่ม Dataset Quality API เก็บเฉพาะใน Supabase Vault ของโปรเจกต์ oezzgzzqgsrpvjeesgva ผู้ใช้เว็บและทีมทั่วไปจะอ่านไม่ได้ โทเค็นเปิดสิทธิ์ให้เซิร์ฟเวอร์ส่งเหตุการณ์เข้า Meta จึงต้องได้รับอนุญาตก่อนสร้าง

## ผลทดสอบ

- ทดสอบโค้ดและหน้าเว็บจำลอง 9 กรณีผ่าน
- ทดสอบฐานข้อมูลใน transaction ที่ rollback: ไม่ส่ง Purchase สำหรับ COD ค้าง, ไม่สร้างเหตุการณ์ซ้ำ, ล็อกงาน, ลองใหม่, คัดค้านและลบข้อมูลจับคู่, คัดค้านก่อนข้อมูลเข้าระบบ ผ่าน
- API ปฏิเสธการเรียก worker และข้อมูลหลังบ้านโดยไม่มีสิทธิ์
- ยังไม่ได้ทดสอบ Meta รับเหตุการณ์จริง เพราะยังไม่มีโทเค็น; ยังไม่อ้างว่ารายงาน Ads ขึ้นยอดแล้ว
- Meta รับเหตุการณ์สำเร็จเป็นคนละขั้นกับจับคู่ยอดให้แอด ต้องตรวจสองขั้นหลังเปิด และไม่รับประกันยอดเท่าหลังบ้านทั้งหมด
